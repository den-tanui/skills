# Dynamic completion wrapper patterns

Use these when the CLI has its own completion protocol, instead of writing static specs.

## Cobra / Go (`cmd __complete`)

Seen in `_gh`, `_yq`, `_sesh`, `_pass-cli`, `_crush` (all identical, generated by cobra). Core logic:

1. Truncate `words` to `$CURRENT`: `words=("${=words[1,CURRENT]}")` (cursor may be mid-line; don't use `$CURSOR` — it breaks with aliases)
2. If the last word looks like `-flag=`, capture the prefix with `BASH_REMATCH` and pass `-P prefix` to compadd later
3. Build `requestComp="${words[1]} __complete ${words[2,-1]}"`; append `""` if the last word is complete (trailing space)
4. `out=$(eval ${requestComp} 2>/dev/null)`
5. Strip the trailing `:directive` line; directive bits:
   - 1 = error (ignore completions)
   - 2 = no space after completion
   - 4 = no file completion
   - 8 = filter file extensions
   - 16 = filter directories
   - 32 = keep order (`-V` instead of sorting)
6. Lines prefixed `_activeHelp_ ` are help text, not completions — show via `_message` or skip
7. Remaining lines are `value\tdescription` — split on tab, feed to `_describe`/`compadd`

Debug: honor `$BASH_COMP_DEBUG_FILE` — append log lines to it when set.

## yargs / Node (`cmd --get-yargs-completions`)

Seen in `_opencode`:

```zsh
_opencode_yargs_completions() {
  local reply
  local si=$IFS
  IFS=$'\n' reply=($(COMP_CWORD="$((CURRENT-1))" COMP_LINE="$BUFFER" COMP_POINT="$CURSOR" cmd --get-yargs-completions "${words[@]}"))
  IFS=$si
  if [[ ${#reply} -gt 0 ]]; then
    _describe 'values' reply
  else
    _default
  fi
}
if [[ "${zsh_eval_context[-1]}" == "loadautofunc" ]]; then
  _opencode_yargs_completions "$@"
else
  compdef _opencode_yargs_completions cmd
fi
```

The `zsh_eval_context` check makes the file work both when autoloaded via `$fpath` and when sourced directly.

## Custom protocol (`cmd completion __complete LINE POINT`)

Seen in `_backlog` — the tool takes the full buffer and cursor position and returns one completion per line:

```zsh
_backlog() {
    local line=$BUFFER
    local point=$CURSOR
    local -a completions
    completions=(${(f)"$(backlog completion __complete "$line" "$point" 2>/dev/null)"})
    (( ${#completions[@]} == 0 )) && return 1
    _describe 'backlog commands' completions
}
compdef _backlog backlog
```

`${(f)"..."}` splits command output into an array on newlines.

## Delegating to git completions

Seen in `_forgit`: for git-adjacent tools, reuse the existing `_git-*` functions (`_git-add`, `__git_recent_commits`, `__git_tags`, `_git-branches`...) in a `case` dispatch on the subcommand, and use `_alternative "files:filename:($(git ...))"` for dynamic lists. Beware: some `_git-*` functions depend on `$curcontext`/`$CURRENT` and must be reimplemented in simplified form when called out of context.
